# Versioning and implementation claims

The canonical specification is authoritative. Published tags identify fixed snapshots; do not move them to incorporate later documentation corrections. Substantive protocol changes require a new version. Editorial and distribution changes must be identified separately. Historical editions remain accessible.

For reproducible implementation and citation, record the specification version and commit SHA. The main branch may contain later supporting documentation.

Suggested reporting descriptions (not certification):
- DT-inspired: uses selected concepts.
- Implements DT v1.3: claims fidelity to the applicable canonical protocol.
- Regression-tested: identifies the exact cases, implementation version, results and limitations.

Passing examples does not establish universal correctness. Report discrepancies through GitHub Issues.
